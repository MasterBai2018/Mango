# `pipeline_llm_to_voice.py` 工具类使用说明

## 1. 工具用途

`tools/pipeline_llm_to_voice.py` 用于完成一条完整流程：

1. 从 CSV / Excel 读取“原始发话”
2. 调用 LLM 生成泛化语音指令
3. 将结果写出为 `txt/json/jsonl`
4. （可选）调用 `RequestIndexTTS` 合成音频
5. 合成前先查 `TestAudio/llm_asr_data/audio_data.db` 的 `tts_audio` 表：
   - 若文本已存在音频路径且文件存在：直接复用
   - 若不存在：执行合成，并把新音频写回数据库

---

## 2. 代码位置

- 主文件：`tools/pipeline_llm_to_voice.py`
- 入口函数：`main()`
- 核心类：`LLMToVoiceTools`

---

## 3. 环境与依赖

## 3.1 Python 依赖

- 必需：`requests`
- 读取 Excel 时需要：`pandas`（通常还需要 `openpyxl`）
- TTS 功能需要可导入：`RequestIndexTTS`

## 3.2 数据库

- 默认数据库路径：`TestAudio/llm_asr_data/audio_data.db`
- 表名：`tts_audio`
- 当前代码适配字段：
  - `text`（主键）
  - `voice`
  - `voice_path`
  - `emotion`
  - `gender`
  - `created_at`

---

## 4. 快速开始（推荐）

你现在可以只传一个 `--input`：

```bash
python3 tools/pipeline_llm_to_voice.py \
  --input tools/templates/24MMLexus_发话一览.xlsx
```

默认参数会自动生效：

- `--output out.json`
- `--output-format txt`
- `--sheet 1-多媒体`
- `--column 中文句式`
- `--tts-output tts_out`（默认开启 TTS 流程）
- `--tts-voice-type random`

> 注意：`--output-format` 默认是 `txt`，如果希望 `out.json` 真的是 JSON 内容，请显式传 `--output-format json`。

## 5. 常用命令示例

## 5.1 只跑 LLM 生成，不做 TTS

通过把 `--tts-output` 置空来关闭 TTS（代码判断 `None` 才关闭，因此建议改代码或手工不传默认；当前默认会开启 TTS）。

推荐实际做法：显式输出 JSON 并保留 TTS，或按需临时修改默认值。

## 5.2 指定输出为 JSON

```bash
python3 tools/pipeline_llm_to_voice.py \
  --input tools/templates/24MMLexus_发话一览.xlsx \
  --output out.json \
  --output-format json
```

## 5.3 指定数据行范围与条数

```bash
  --row 8-9 \
```

## 6. 参数说明

## 6.1 输入输出相关

- `--input`：输入文件，支持 `.csv/.xlsx/.xls`（必填）
- `--output`：输出文件路径，默认 `out.json`
- `--output-format`：`txt | json | jsonl`，默认 `txt`
- `--column`：读取列名，默认 `中文句式`
- `--sheet`：Excel sheet 名，默认 `1-多媒体`
- `--limit`：仅处理前 N 条
- `--row`：处理指定数据行范围，如 `8-9` 或 `8`

## 6.2 LLM 相关

- `--extra-instruction`：附加系统提示词
- `--model`：覆盖默认模型（默认 `deepseek-chat`）
- `--api-url`：覆盖默认接口地址
- `--api-key`：覆盖默认 API Key

## 6.3 TTS 相关

- `--tts-output`：TTS 输出目录（默认 `tts_out`）
- `--tts-voice-type`：参考音色（默认 `random`）
- `--tts-scp`：生成参考 `scp/text.ref`
- `--tts-silence`：前后静音毫秒，默认 `800`
- `--tts-threads`：并发线程，默认 `2`
- `--tts-retry`：重试次数，默认 `1`
- `--tts-source`：`base | cases`，默认 `cases`
- `--tts-max-per-base`：每条 base 最多合成 N 条 case
- `--tts-limit`：总共最多合成 N 条

---

## 7. 数据库复用逻辑（重点）

当开启 TTS（`--tts-output` 非空）时：

1. 从 LLM 结果抽取待合成文本列表 `tts_texts`
2. 对每条文本按 `(text, voice)` 查询 `tts_audio.voice_path`
3. 若路径存在且文件存在：记为“已存在复用”
4. 若不存在：加入 `missing_texts` 批量合成
5. 合成后解析 `text.ref` / `text.scp(or scp)`，得到 `text -> audio_path`
6. 将新增结果写入 `tts_audio`
7. 最终打印统计：
   - 总输入条数
   - 已存在复用
   - 新增合成入库

---

## 8. 输出文件说明

- LLM 输出（由 `--output-format` 决定）：
  - `txt`：`原始发话\t生成指令`
  - `json`：记录数组
  - `jsonl`：逐行 JSON
- TTS 输出目录通常包含：
  - `*.wav`
  - `text.ref`
  - `text.scp` 或 `scp`
  - `tts_texts.missing.txt`（本次缺失需合成文本）

## 9. 常见问题

## 9.1 报错 `导入 RequestIndexTTS 失败`

说明当前环境找不到 `RequestIndexTTS`。请检查：

- 相关模块是否在 Python 路径中
- 当前终端是否使用了正确虚拟环境

## 9.2 数据库有记录但仍重复合成

可能原因：

- `voice` 不一致（查询按 `text + voice`）
- `voice_path` 指向文件已不存在（会视为缺失并重合成）

## 9.3 `out.json` 不是 JSON 格式

因为默认 `--output-format txt`。请显式加：

```bash
--output-format json
```

---

## 10. 建议优化（可选）

如果你希望“默认不跑 TTS”，建议把 `--tts-output` 默认值从 `tts_out` 改成 `None`，这样仅传 `--input` 时只生成文本结果，不会触发音频合成。
